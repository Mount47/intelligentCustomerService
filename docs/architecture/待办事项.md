# 当前待办事项

这里只保留尚未完成或仍需加强的事项。已实现内容记录在
[项目状态](项目状态.md)，历史设计保存在 `archive/`。

## 优先级一：可靠投递

数据库写入消息和会话后，再调用消息队列投递，目前存在提交成功但投递失败的窗口。

建议增加事务事件表：

```text
同一数据库事务写入消息、会话和待投递事件
→ 独立投递程序读取未发送事件
→ 成功发送后标记完成
```

验收要求：

- 队列短暂不可用后仍能补投；
- 重复投递不会重复处理业务；
- 有积压数量和失败告警。

## 优先级二：数据库迁移管理

当前模型可以创建表，但完整生产流程应使用数据库迁移工具管理结构变化。

验收要求：

- 空数据库可以按迁移顺序升级；
- 已有数据可以安全升级；
- 可以检查当前数据库版本；
- 持续集成验证迁移可执行。

## 优先级三：共享熔断状态

当前熔断器在单个工作进程内有效。多个工作进程之间不共享状态，模型服务故障时仍可能分别探测。

可根据真实部署规模选择：

- 保留进程内熔断，并由统一模型网关限流；
- 使用 Redis 协调共享状态和探测许可；
- 交给服务网格或模型网关负责。

## 优先级四：扩大真实模型评测

当前确定性回归较完整，但真实模型样例量仍有限。

建议：

- 增加口语、错别字、多意图和长对话样例；
- 保存模型、版本、时间、令牌和成本；
- 对失败样例进行人工复核；
- 将真实失败回流为测试或新评测样例。

## 优先级五：更完整的内容安全

当前回复后检查主要依赖禁语扫描。后续可以增加：

- 回复中的金额和状态与工具结果核对；
- 敏感信息检查；
- 企业政策规则；
- 人工抽检和申诉流程。

## 暂不实施

- 多智能体编排；
- 向量记忆；
- 开放领域知识库；
- 真实支付退款；
- 企业统一身份平台。

这些能力不是当前项目主线，除非业务目标发生变化。
