# 安全与一致性

## 安全目标

系统重点防止：

- 越权查询他人订单；
- 未经确认创建低风险退款申请；
- 高风险退款自动完成；
- 网络重试和并发导致重复退款；
- 队列重复投递导致重复回复；
- 较慢的旧任务覆盖新状态；
- 模型绕过技能边界调用写工具；
- 模型输出不当承诺。

## 多层权限防护

```text
接口登录身份
→ 订单和工单归属校验
→ 技能工具白名单
→ 服务端参数绑定
→ 服务层再次校验资源归属
```

提示词只负责告诉模型不要越权，以上代码规则负责保证模型不能越权。

## 危险写操作

退款申请、人工升级和状态更新等危险工具不会由模型循环执行。即使模型或模型服务异常地产生
这类调用，调用前检查也会返回拒绝结果。

真正写操作由业务技能收口阶段根据数据库事实确定性执行。

## 退款幂等

### 请求级

- 客户端幂等键识别同一请求重发；
- 请求参数指纹识别同一键携带不同参数；
- 业务去重键识别同一业务重复申请；
- 数据库唯一约束裁决真实并发。

### 会话级

同一订单已经存在进行中的退款申请时，新的对话轮次不会再创建一条。

Redis 只用于限流和削峰，不承担退款唯一性的最终保证。

## 工单状态机

状态机集中声明允许的状态转移，非法转移抛出异常。等待确认、等待补信息、转人工和完成状态具有
不同后续行为，不能只用一个“处理中”状态代替。

数据库另外保存状态变更历史，包括操作者、原因和关联会话。

## 并发提交

工作进程最终通过工单状态与版本比较更新。比较失败时整个事务回滚，防止出现：

- 工单状态没更新但退款申请已经留下；
- 回复已经写入但状态属于另一轮；
- 多个工作进程分别创建派生工单。

## 回复检查

系统提示词要求模型不承诺退款、赔偿或送达时间，最终回复还会经过禁语检查。命中时替换成固定
安全话术。

当前禁语扫描属于基础防线，不能代替完整的事实核验和企业级内容安全系统。
