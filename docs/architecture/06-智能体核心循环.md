# 智能体核心循环

## 固定处理管道

```text
恢复初始状态
→ 处理确认态或补信息态
→ 识别意图
→ 超范围和低置信短路
→ 路由业务技能
→ 技能制定计划
→ 运行模型与工具循环
→ 技能进行确定性收口
→ 回复检查
→ 状态机转移
```

所有业务技能共用同一条管道，避免每个技能分别实现工具权限、错误处理、令牌统计和状态收口。

## 三个核心对象

### 智能体上下文

保存本次会话、工单、用户、订单、消息、历史、意图、技能、工具记录、令牌统计和最终决策。

### 技能计划

声明：

- 系统任务说明；
- 本技能允许的工具；
- 最大循环次数；
- 缺少的必要信息。

### 最终决策

包含：

- 回复；
- 目标状态；
- 是否转人工；
- 转人工原因；
- 仍需补充的信息。

## 模型与工具循环

```text
准备系统任务说明、历史和当前消息
→ 只提供技能允许的工具说明
→ 调用模型
→ 如果模型请求工具：
     校验白名单和危险工具
     绑定可信用户与订单参数
     执行工具并记录审计
     将工具结果返回模型
     继续下一轮
→ 如果模型结束：
     保存模型回复并退出
→ 达到最大轮数：
     停止继续调用
```

最大轮数防止模型陷入重复调用。工具调用编号用于将每个结果准确对应回原调用。

## 计划与收口为什么分开

计划阶段告诉模型可以查询什么；收口阶段根据数据库事实决定实际业务动作。

例如退款技能可以让模型查询订单和政策，但真正创建退款申请、判断高风险和转人工都由
`finalize` 中的确定性代码完成。
