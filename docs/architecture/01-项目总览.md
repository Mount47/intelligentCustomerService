# SupportFlow 项目总览

## 一句话定位

SupportFlow 是一个面向电商售后的有边界智能客服系统。它用大模型理解用户语言、
选择只读查询工具并组织回复；退款资格、订单归属、二次确认、状态流转和数据写入由
确定性代码与数据库负责。

它不是开放聊天机器人，也没有直接调用支付渠道完成真实资金退款。

## 当前业务范围

系统支持：

- 查询本人订单、商品明细和物流状态；
- 识别物流异常并创建催件工单；
- 申请退款、咨询退款政策、确认或取消退款；
- 对高金额、特殊商品、超售后期限等情况转人工；
- 对投诉、明确要求人工、签收未收到等情况转人工；
- 用户和管理员两种角色的前端操作；
- 会话进度推送、工具审计、成本统计、服务时限和质量记录。

系统不声称：

- 已接入支付渠道完成真实退款；
- 能回答开放领域问题；
- 接入层压力测试代表真实大模型吞吐；
- 执行时间线是模型隐藏思维过程；
- 规则和模拟模型评测能够证明线上语义泛化能力。

## 总体结构

```text
用户前端
  → 接口层：认证、归属校验、限流、消息去重
  → 数据库落消息并创建处理会话
  → 消息队列削峰
  → 智能体运行器：抢占任务、恢复上下文、控制事务
  → 智能体核心：意图、路由、工具循环、业务收口
  → 服务层：订单、物流、退款、工单、服务时限、知识
  → 数据库：事实、状态、审计、质量记录
  → 进度推送或轮询返回结果
```

## 最重要的设计原则

### 大模型处理语言，代码处理业务

大模型适合：

- 理解口语化诉求；
- 在允许范围内选择只读工具；
- 根据可信查询结果组织解释。

确定性代码负责：

- 用户身份和订单归属；
- 退款风险与资格；
- 高风险转人工；
- 用户确认；
- 状态机；
- 幂等、事务和数据库写入。

### 提示词负责引导，代码负责保证

提示词会要求模型不编造、不承诺、只使用允许工具，但系统不会相信模型一定遵守。
工具白名单、危险工具拒绝、服务端参数绑定、状态机和数据库约束才是最终保证。

### 消息可能重复，任务也可能重复

系统默认网络会重试、队列可能重复投递、多个工作进程可能并发处理。因此消息、退款和
工单状态分别设置了数据库唯一约束、会话抢占和版本比较更新。

## 学习入口

理解项目时不要先钻某个函数。建议按以下顺序：

```text
业务范围
→ 数据模型
→ 请求链路
→ 智能体运行器
→ 意图与多轮
→ 核心循环
→ 工具与技能
→ 安全与一致性
→ 模型与记忆
→ 观测、评测与部署
```
