# 当前架构决策

这里记录仍然适用于当前实现的主要选择。完整演进历史保存在 `archive/完整决策历史.md`。

## 单智能体配合业务技能

售后的核心难点是业务约束、状态一致性和安全写入，不是角色数量。统一核心管道可以集中处理
工具权限、审计、令牌、错误和状态收口。

## 危险写操作不交给模型

模型只能在技能允许范围内调用只读工具。退款申请、人工升级和工单状态写入由业务代码根据数据库
事实执行。

## 数据库承担最终一致性

Redis 用于限流和削峰，不承担退款唯一性。消息和退款分别使用数据库唯一约束处理并发竞争。

## 会话精确绑定消息

每个智能体会话绑定触发消息，工作进程不能依赖“最新用户消息”。可处理状态通过条件更新原子抢占。

## 工单使用版本比较更新

工作进程提交时必须证明工单仍处于自己读取的状态和版本，否则整笔事务回滚。

## 事件流传输状态，不暴露隐藏思维

前端接收完整会话状态变化，断线后退回轮询。执行时间线只展示可审计步骤。

## 评测分层

模拟模型负责确定性回归，真实模型负责语义效果验证，线上会话另有基于数据库事实的流程质检。

## 记忆分层

业务硬事实查数据库，流程状态保存在工单，对话历史按令牌预算保留和摘要。

## 模型服务使用熔断

模型是高延迟外部依赖。连续服务故障后快速失败或降级，半开阶段限制探测请求，避免故障放大。

## 前端只展示可信状态

真实接口失败必须显式展示错误，模拟数据仅用于明确的演示模式，不能悄悄伪装成真实处理结果。
