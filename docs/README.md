# SupportFlow 文档入口

这里是项目文档的统一入口。

## 事实优先级

遇到描述不一致时，按以下顺序判断：

1. 当前代码与自动化测试
2. `architecture/` 下的当前架构文档
3. `guides/` 下的学习与运行指南
4. `interview/` 下的面试表达材料
5. `archive/` 下的历史记录

历史记录用于说明项目如何演进，不能用来判断当前实现。

## 从哪里开始

- 第一次了解项目：读 [项目总览](architecture/01-项目总览.md)
- 准备系统学习：读 [分模块学习路线](guides/分模块学习路线.md)
- 准备运行项目：读 [运行手册](guides/运行手册.md)
- 查询当前完成情况：读 [当前项目状态](architecture/项目状态.md)
- 理解为什么这样设计：读 [当前架构决策](architecture/架构决策.md)
- 查看真实踩坑：读 [实际问题与解决](incidents/实际问题与解决.md)

本地若存在 `interview/`，它是个人面试准备材料，不纳入公开版本管理，也不作为实现真值。

## 文档维护规则

- 表数量、工具数量、测试结果等动态事实只在
  [当前项目状态](architecture/项目状态.md) 中维护。
- 当前架构只在 `architecture/` 中维护。
- 学习资料不重复声明动态数字，而是链接到项目状态。
- 面试资料侧重“怎么讲”，不能成为实现依据。
- 已完成事项从待办中移除；重要设计变化追加到架构决策。
- 旧设计和旧状态统一放入 `archive/`，不再更新。
