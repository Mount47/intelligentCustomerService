# docs 导航（先读这页）

每个文档是什么、该往哪写。**新会话/找资料从这里开始。**

## 真值优先级
**代码 + 测试 > git log > 文档**。三者不一致，信代码。

## 文档地图

| 文档 | 是什么 | 何时读/写 |
|---|---|---|
| `项目需求介绍/项目需求.md` | 原始需求(初始 prompt) | 想知道"最初要做什么" |
| `项目设计/01-总体设计.md` | **稳定架构**：Agent 链路/状态机/表/三层幂等/guardrails | 想懂"系统怎么搭的"，不常变 |
| `项目设计/DECISIONS.md` | **决策记录(ADR)**：主动的设计选择 + 为什么 | 想知道"为什么这么设计" |
| `项目设计/STATUS.md` | **动态状态/导航**：做到哪、下一步、里程碑 | 每次开工先看；收尾更新 |
| `项目设计/定位与亮点.md` | **面试底稿**：对标 + 五大亮点 | 准备讲述/复盘 |
| `项目运行/运行手册.md` | **怎么跑**：启动前后端/配置/排查 | 要把项目跑起来 |
| `项目运行/实际问题与解决.md` | **踩坑日志**：实测发现的问题 + 修法 | 撞到 bug / 复盘踩过的坑 |
| `项目运行/待办事项.md` | **待办/功能构想**：未实现的、设计先行 | 规划下一步该做什么 |

## 关键边界：决策(DECISIONS) vs 实际问题(实际问题与解决)

两者都"记录发生过的事"，容易写错地方。判断法：

| | `DECISIONS.md` | `实际问题与解决.md` |
|---|---|---|
| 性质 | **主动决策**(为什么这么设计) | **被动踩坑**(实测撞出的问题+修法) |
| 时态 | 前瞻、稳定、不常改 | 回顾、动态、持续追加 |
| 例 | ADR-14 数据库分层、读写分离 | #5 工具 FAILED、#8 重复草稿、"不确定"误判 |
| 一句话 | "我**决定**这么做，因为…" | "实际**跑出了** X 问题，根因 Y，修法 Z" |

> 口诀：**"方向选择" → DECISIONS；"实测踩坑" → 实际问题。**

## 关键边界：待办(待办事项) vs 决策(DECISIONS)

按**时间线**分，不重复：

| | `待办事项.md` | `DECISIONS.md` |
|---|---|---|
| 时态 | **未来**：还没做 | **已决**：通常已做 |
| 性质 | 主动计划/构想，设计先行 | 主动决策 + 为什么，锁定不重写 |
| 例 | TODO-1 会话摘要、TODO-2 上下文溢出 | ADR-14 数据库分层、读写分离 |

> **生命周期**：待办(计划) → 实现 → 若是值得记的架构决策则**固化成 ADR 进 DECISIONS + 从待办删除**。做完要搬家，别两边并存。

## 三个"记录类"文档一句话区分
- **待办事项** = 打算怎么做（未来）
- **DECISIONS** = 已决定并做了，为什么（已决）
- **实际问题与解决** = 已经踩过的坑 + 修法（过去）

## 三类文档的节奏

- **稳定层**(需求/总体设计/定位)：少改。
- **决策层**(DECISIONS)：追加式，不重写。
- **动态层**(STATUS/实际问题/待办)：常更，反映当下。
